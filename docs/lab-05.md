## 1. Структура репозитория

```text
KPO/

    FitnessCenter.Api/     ASP.NET Core, правило записи на слот

```

Каркас соответствует диаграмме компонентов лабораторной № 4: клиент не читает MongoDB, правило «нельзя записаться дважды» исполняется в API. Коллекции MongoDB на этом шаге ещё не подключаются: для проверок достаточно политики записи и одного демонстрационного слота `morning-yoga` на 2 места.

## 2. Коммиты

Сообщения оформляются по Conventional Commits:

```text
<type>(<scope>): <что сделано>
```

Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `ci`, `chore`, `build`. Область — модуль из лабораторной № 4 (`booking`, `client`) или опускается.

Проверка автоматическая. В CI job `commitlint` на pull request прогоняет сообщения от базы ветки до головы. Конфигурация — `commitlint.config.js`, пакеты `@commitlint/cli` и `@commitlint/config-conventional`. Сообщения слияния (`Merge branch ...`) commitlint пропускает.

Примеры из истории ветки `feature/scm-pipeline`:

| Коммит | Сообщение |
|---|---|
| chore | `chore: pin editor settings and the public npm registry` |
| API | `feat(booking): reject a duplicate booking and decrement free seats` |
| Тесты | `test(booking): cover seat decrement and duplicate booking` |
| Клиент | `feat(client): add the fitness center angular shell` |
| Пайплайн | `ci: check commits, lint, tests and build on pull requests` |

## 3. Ветвление

Выбран укороченный Git Flow: у лабораторной несколько основных веток, а этапы сдачи из лабораторной № 3 закрываются отдельным срезом, а не очередным feature.

| Ветка | Назначение |
|---|---|
| `main` | Версия, которую можно показать. Только через pull request |
| `develop` | Интеграция задач текущего этапа |
| `feature/<задача>` | Одна задача трекера |
| `release/vX.Y.Z` | Срез в конце этапа, затем слияние в `main` и обратно в `develop` |

## 4. Слияние и защита веток

Порядок, который зафиксирован в истории:

1. Коммиты накапливаются в `feature/scm-pipeline`.
2. Ветка сливается в `develop` с merge-коммитом, без перезаписи истории.
3. От `develop` открывается `release/v0.2.0`.
4. Релиз сливается в `main`, на `main` ставится тег.
5. Тот же релиз сливается обратно в `develop`, чтобы метка релиза не потерялась.

Прямой push в `main` и `develop` на GitHub закрывается правилами ветки. Скрипт `scripts/protect-branches.ps1` включает для обеих веток:

- изменения только через pull request;
- обязательные проверки `CI / commitlint`, `CI / lint`, `CI / test`, `CI / build`;
- запрет force-push.

Чужое approve не требуется: разработчик один, контроль — это статус-чеки. Правила включаются на GitHub после push, потому что их хранит сервер, а не коммит. До этого момента локальный git push в `main` технически возможен.

## 5. Контроль качества кода

| Язык | Инструмент | Что считает ошибкой |
|---|---|---|
| C# | `.editorconfig` и `dotnet format --verify-no-changes` | отступление от стиля |
| TypeScript и шаблоны Angular | ESLint (`ng lint`), правило `complexity` | стиль и слишком сложные функции |
| Клиент | Prettier `--check` | формат файлов `src` |

Job `lint` в `.github/workflows/ci.yml` запускает все три проверки на каждый push в `main`/`develop` и на каждый pull request.

## 7. Пайплайн

Файл `.github/workflows/ci.yml`.

| Job | Когда | Результат |
|---|---|---|
| `commitlint` | каждый push и pull request | сообщения коммитов |
| `lint` | после выгрузки кода | `dotnet format`, `ng lint`, Prettier |
| `test` | если lint зелёный | 9 тестов API и 2 теста клиента, покрытие |
| `build` | если test зелёный | артефакты `dotnet publish` и `ng build` |
| `image` | только push в `main` | образ API собирается и не публикуется |

Образ описан в `server/FitnessCenter.Api/Dockerfile`, локальный запуск — `docker-compose.yml`. Это тестовый контур API из диаграммы развертывания лабораторной № 4. GitHub Pages для этого приложения не используется: туда не встают API и база.

Снимок метрик по концу этапа запускается вручную: `.github/workflows/metrics.yml`, входные параметры `stage`, `since`, `until`. Локально то же делает `scripts/collect-metrics.ps1`.

Проверки, уже выполненные на машине 16.10.2026: `dotnet format` без правок, `dotnet test` — 9 пройдено, `ng lint` без замечаний, `ng test` — 2 пройдено, `ng build` собрал `client/dist/client`. Прогон GitHub Actions появится после push.
